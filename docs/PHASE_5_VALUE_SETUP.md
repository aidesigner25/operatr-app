# Phase 5: automatic value estimates

Apply `supabase/migrations/202611040002_value_estimates.sql` in the Supabase SQL Editor for the same project used by Operatr. This migration was revised before its first application to include automated assessments; use the current file. Then apply `supabase/migrations/202611050001_value_trajectory.sql` to add the local-time weekly and monthly chart. No new environment variables are required. Restart the development server if needed.

After a response completes, Operatr asks the same selected provider and model to assess the incremental work in that response. It sends a compact excerpt of recent context, the current request, the response, and research source counts in one short provider assessment, with one bounded retry for transient failures or invalid output. This call uses the user's provider key, may incur usage costs, and allows up to 30 seconds for model inference plus short independent database windows after the response has streamed. A complete valid JSON result is accepted immediately and the remaining provider stream is cancelled. Its output is constrained: quick or nonqualifying tasks yield no value estimate; qualifying tasks must estimate 30–960 minutes. This is a model judgment, not a measurement, and can be wrong. A failed assessment or failed write is shown with a reason and never creates a fabricated estimate. Retry automatic uses the saved response and the conversation’s currently selected model; it does not rerun research and may incur model usage. Existing historical responses are not backfilled automatically.

The assessment and operating rate at the time it is saved appear under the completed response. Users can edit hours and minutes, add a manual estimate to nonqualifying or older responses, or remove an estimate. Edits capture the current operating rate; changing the rate alone does not change existing estimates. Separate response estimates can overlap. Manual document/Sheet export clicks are not assessed as separate tasks.

The dashboard totals only positive estimates and groups the most recent six calendar months and the current Monday–Sunday week in the viewer's browser time zone, by the original assessment creation date. It sums each estimate's value rounded to cents. Values are estimated capital equivalents, not verified time, actual ROI, cash earned, or measured performance. One assessment is allowed per response; owner-only row-level security scopes records and aggregate queries. Estimates are removed when the underlying message is deleted.

Smoke test with two accounts: (1) ask a quick question and confirm it shows no qualifying value, (2) run a meaningful research task and check its time and dollar estimate, (3) edit hours/minutes and verify the dashboard totals and monthly and weekly graphs update, (4) add a manual estimate to the quick response and remove it, and (5) verify the other account cannot see those records. Model estimates and timeouts can vary; a missing estimate is reported rather than guessed.
